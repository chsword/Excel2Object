# v2.8.0

发布日期：2026-09-13

## 概述

本版本修正导入过程中的错误处理方式：不再将异常写入标准输出，改由回调上报，并可由调用方决定是否中止导入；同时将公式求值器的创建由逐单元格改为按工作簿一次。

## 变更明细

### 1. 修复：读取失败不再写入标准输出

`ExcelImporter` 此前在三处捕获异常后调用 `Console.WriteLine` 并继续执行。类库向标准输出写日志本身即不妥，更严重的是调用方只能得到空值，无从得知数据为何缺失。

现移除全部标准输出，改为通过 `ExcelImporterOptions.OnCellError` 上报。默认不设回调，此时该单元格取默认值并继续导入，行为与既有版本一致。

```csharp
public class Order
{
    [ExcelTitle("订单号")] public string No { get; set; } = "";
    [ExcelTitle("下单时间")] public DateTime? PlacedAt { get; set; }
}

var errors = new List<ExcelImportError>();
var orders = new ExcelImporter()
    .ExcelToObject<Order>(File.ReadAllBytes("orders.xlsx"), options => options.OnCellError = errors.Add)
    .ToList();

foreach (var error in errors)
    Console.WriteLine($"{error.SheetTitle}!{error.CellReference} 读取失败：{error.Exception.Message}");
```

回调参数 `ExcelImportError` 提供工作表名称、行列序号、单元格地址（例如 `B3`）与原始异常。

两类失败的后续处理并不相同，回调只负责告知：

| 失败类型 | 例子 | 后续处理 |
| --- | --- | --- |
| 读取失败 | 日期序列号超出 Excel 日历 | 该单元格取默认值，导入继续 |
| 转换失败 | 文本 `abc` 写入 `int` 属性 | 上报之后照旧抛出，导入中止（与既有版本一致） |

若希望读取失败也中止导入，在回调中抛出异常即可：

```csharp
options.OnCellError = error => throw error.Exception;
```

### 2. 改进：公式求值器按工作簿创建

此前每遇到一个公式单元格即调用一次 `WorkbookFactory.CreateFormulaEvaluator`。求值器的构造会读取工作簿的公式环境，逐单元格创建将使含公式的表格导入明显变慢。现于一次导入过程中按工作簿创建一次并全程复用。

## 升级影响

既有代码无需修改。若此前依赖标准输出中的异常信息进行排查，请改为设置 `OnCellError` 回调。
