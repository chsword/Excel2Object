# v2.9.0

发布日期：2026-09-13

## 概述

本版本新增合并单元格：既可让某列中连续相同的值自动并成一格，也可直接指定要合并的区域。

## 变更明细

### 1. 新增：按列合并连续相同的值

分组报表中同一省份、同一类别的若干行通常只需显示一次，此前只能导出后手工合并。

```csharp
var bytes = ExcelHelper.ObjectToExcelBytes(orders, options =>
{
    options.MergeRepeatedColumns.Add("省份");
    options.MergeRepeatedColumns.Add("城市");
});
```

规则如下：

- 仅**相邻且相等**的行参与合并，跨越其他取值的相同值不会并到一起；
- **空单元格不参与**：若干行都没有值，并不意味着它们属于同一组；
- 各列**彼此独立**判断。若需要「同一省份之下的城市才合并」这类层级语义，请自行保证数据已按层级排序；
- 数值按其值而非显示文本比较，格式不同但数值相同的两行仍会合并。

### 2. 新增：另行指定区域

列以标题指定，行以数据行的序号（自 1 计起）指定：

```csharp
// 表头行上，把「省份」到「城市」两列并成一格
options.MergedRegions.Add(new MergedRegion("省份", "城市"));

// 「备注」列的第 1 至第 3 行数据并成一格
options.MergedRegions.Add(new MergedRegion("备注") { FirstRow = 1, LastRow = 3 });
```

之所以不以 `A1:C1` 这样的地址为主：列在工作表中的位置由 `Order`、特性的声明顺序以及公式列的插入位置共同决定，行数则取决于数据条数，二者在编写导出代码时都无从得知。确已知道最终布局时仍可直接写地址，字符串会隐式转换为一处区域：

```csharp
options.MergedRegions.Add("A1:C1");
```

行序号小于 1、超出本次导出的数据行数、地址写法不合法（例如 `A1-C1`），或区域只占一个单元格，均会抛出 `Excel2ObjectException` 并说明缘由。

### 3. 重叠区域会被拒绝

Excel 视重叠的合并区域为损坏文件。导出时若两个区域重叠，抛出 `Excel2ObjectException` 并指出与哪一个重叠，而非写出打不开的文件。

### 4. 公式列不参与按值合并

公式列写进单元格的是公式，其结果由 Excel 打开时才算出，导出时无从比较。对公式列使用 `MergeRepeatedColumns` 会抛出 `Excel2ObjectException`，而非按公式文本比较——后者会因每行的引用不同（`=A2+B2`、`=A3+B3`）而永不合并，看似支持实则无效。

## 注意事项

- 被并入的单元格仍保留各自的值，Excel 只显示左上角那一个。因此导回对象时每一行的数据依然完整，与未合并时一致。
- Excel 中含合并单元格的区域无法排序。若同时启用 `AutoFilter`，筛选可用，排序会被 Excel 拒绝。
- 分组表的合并区域数量与行数同阶。NPOI 自带的 `AddMergedRegion` 对每个新区域都要扫描已有全部区域，8000 个区域即需数秒；本库自行完成重叠校验（同一列内的各段天然互不相交，无需两两比对），再走其 `AddMergedRegionUnsafe` 写入，两万行的分组表因此仍在毫秒级完成。
