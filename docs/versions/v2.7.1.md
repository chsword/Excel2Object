# v2.7.1

发布日期：2026-09-13

## 概述

本版本修正 v2.7.0 引入的样式表中数字格式（`Format`）的作用范围问题，并对样式解析过程作性能优化。样式表本身的用法未发生变化，无需修改既有代码。

## 变更明细

### 1. 修复：`Format` 的作用范围由声明位置决定

样式表允许在多个层级声明 `Format`，但 v2.7.0 未区分声明位置，导致三种错误行为。本版本确立如下规则：

- 为**某一列**声明的格式（`Column("标题")` 或 `[ExcelColumn(Format = ...)]`）表示对该列的明确意图，按声明执行；
- 为**全体单元格或奇偶行**声明的格式（`Cells`、`OddRows`、`EvenRows`）为默认值，仅作用于与其类型相符的列。

据此修正的三个问题：

| 场景 | v2.7.0 的行为 | 本版本的行为 |
| --- | --- | --- |
| `[ExcelColumn(Format = "yyyy-MM-dd HH:mm:ss")]` 与 `Cells(s => s.Format("yyyy-MM-dd"))` 同时存在 | 特性被覆盖，时分秒丢失 | 特性优先，保留时分秒；仅 `Column("时间", ...)` 可覆盖 |
| `Cells(s => s.Format("yyyy-MM-dd"))` 作用于 `decimal` 列 | `12.5` 显示为 `1900-01-12` | 日期格式不作用于数值列 |
| `Cells(s => s.Format("#,##0.00"))` 作用于字符串列 | 文本格式 `@` 被覆盖，前导零保护失效 | 文本列仅接受为该列声明的格式 |

```csharp
public class Order
{
    [ExcelColumn("下单时间", Format = "yyyy-MM-dd HH:mm:ss")]
    public DateTime PlacedAt { get; set; }

    [ExcelTitle("金额")] public decimal Amount { get; set; }
    [ExcelTitle("订单号")] public string No { get; set; }
}

var bytes = ExcelHelper.ObjectToExcelBytes(orders, options =>
{
    // 作为默认值声明：仅作用于日期列，数值列与文本列不受影响
    options.Styles.Cells(s => s.Format("yyyy-MM-dd"));

    // 为该列明确声明：覆盖特性上的 Format
    options.Styles.Column("下单时间", s => s.Format("yyyy年MM月dd日"));
});
```

### 2. 改进：边框宽度支持 CSS 关键字

`Border` 系列方法除以像素表示宽度外，亦接受 CSS 的 `thin`、`medium`、`thick` 三个关键字。写法无法识别时，异常信息将指出未能识别的具体片段。

```csharp
options.Styles.Cells(s => s.Border("medium dashed red"));
```

### 3. 改进：样式解析由按单元格改为按列按行

样式的合并与缓存键的构造此前对每个单元格各执行一次，现改为按「列 × 行奇偶」解析一次并在整表复用。在十万行规模的导出中，可减少数百万次样式合并与字符串拼接。

## 升级影响

如既有代码依赖 v2.7.0 中「`Cells` 上的格式覆盖 `[ExcelColumn(Format)]`」这一行为，升级后该格式将不再生效；请改为在 `Column("标题")` 上声明。其余用法保持兼容。
