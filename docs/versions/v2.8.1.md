# v2.8.1

发布日期：2026-09-13

## 概述

本版本修复两处仅在 .NET Framework 上出现的缺陷。两者均由测试补齐多目标框架后查出——此前测试只在 net10.0 上运行，这类差异无从暴露。

## 变更明细

### 1. 修复：.NET Framework 上样式互相覆盖

`string.Join(string, params object[])` 在 .NET Framework 上有一处实现差异：**首个元素为 `null` 时直接返回空字符串**。样式与字体的缓存键均以字体色打头，而多数样式并不设置字体色，于是所有此类样式得到相同的键，共用同一个单元格样式。

后果是自 v2.7.0 起，在 .NET Framework 上运行时：

- `EvenRows` / `OddRows` 的隔行底色不生效
- `Border` 系列设置的边框不生效
- `Bold`、`Italic`、`Underline` 等字体设置相互覆盖
- `[ExcelColumn]` 上的单元格样式同样受影响

两处缓存键改为字符串插值，各属性均参与其中。.NET（Core）上的行为始终正确，不受影响。

```csharp
// 在 .NET Framework 上，此前两列会共用同一个样式，底色与边框都不出现
options.Styles
    .EvenRows(s => s.Background("#F2F2F2"))
    .Column("金额", s => s.Border("1px solid #D0D0D0"));
```

### 2. 修复：.NET Framework 上导入数值丢失精度

数值单元格读入非字符串属性时先转为文本再转换。.NET Framework 的默认数值格式为 `G15`，会丢掉低位；其 `"R"` 格式对少数值给出的表示同样无法往返（已知缺陷）。日期序列号 `46276.6046875` 这类值读入 `double` 属性时因此与原值不符。

现按 `"R"` 渲染后验证一次能否解析回同一个数值，确实不能时才退回 17 位有效数字。常见数值因此不会平白变成 `0.10000000000000001` 这样的写法。

## 工程

测试项目改为多目标框架运行：`net10.0` 与 `net8.0` 在各平台运行，`net472` 在 Windows 上运行。`netstandard2.0` 与 `netstandard2.1` 不是可运行的目标框架，其产物仍由编译保证。CI 另增 `workflow_dispatch`，可在合并前手动触发完整矩阵。
